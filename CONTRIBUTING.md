# Contributing to bacnet_plugin

Bug reports, interoperability findings and pull requests are welcome. Use
the issue forms on GitHub; for device specific problems include the vendor
and model, logs with `logLevel: BacnetLogLevel.debug` and, if possible, a
Wireshark capture.

## Setup

```bash
git clone --recurse-submodules https://github.com/gencto/bacnet_plugin.git
cd bacnet_plugin
# existing clone: git submodule update --init
dart pub get --no-example
```

`native/bacnet-stack` is a git submodule pinned to a reviewed bacnet-stack
commit.
The native library is compiled by `hook/build.dart` the first time a test,
app or benchmark runs, so a C compiler is required: clang or gcc on Linux,
Xcode on macOS/iOS, Visual Studio with the C++ workload on Windows, the
Android NDK installed by Flutter for Android.

## Project structure

```
lib/
  bacnet_plugin.dart     public API (everything else in lib/src is private)
  testing.dart           FakeBacnetClient for application tests
  src/
    client/              BacnetClient
    server/              BacnetServer
    utilities/           DeviceScanner, PropertyMonitor
    models/              value types and events
    core/                configuration, exceptions, logging
    constants/           BACnet enumerations (generated)
    testing/             FakeBacnetClient and in-memory devices
    codec/               bounds checked BACnet encoder/decoder
      reader.dart, writer.dart       tags and primitive values
      value_encoding.dart            application values, datatype inference
      requests.dart, responses.dart  service encoders/decoders
    native/              worker isolate and FFI
      bacnet_system.dart  main isolate side, reference counted stack
      worker.dart         worker isolate: glue between the layers below
      scheduler.dart      request scheduling (pure Dart, unit tested)
      engine.dart         typed facade over the C API
      native_event.dart   reader of the native event buffer
      protocol.dart       messages between the isolates
      bindings.g.dart     generated by ffigen
native/src/              C engine around bacnet-stack (see bp_internal.h)
hook/build.dart          native build for every platform
test/                    mirrors lib/src; test/integration talks to a
                         server process over the loopback interface
tool/                    generators, demo server, interop client
benchmark/               load tests
example/                 Flutter demo app
```

## Checks

Run what CI runs before opening a pull request:

```bash
dart format lib test hook benchmark tool
dart analyze --fatal-infos lib test hook benchmark tool
dart test                       # unit and integration tests
dart test --exclude-tags integration

cd example
flutter analyze
flutter test integration_test/app_test.dart -d flutter-tester
```

Native changes must also compile without warnings:

```bash
gcc -fsyntax-only -Wall -Wextra -Werror -Wno-unused-parameter \
  -DBACDL_BIP=1 -DPRINT_ENABLED=0 -DBACNET_STACK_STATIC_DEFINE \
  -Inative/bacnet-stack/src -Inative/src native/src/*.c
```

Format C code with `clang-format` (style in `native/src/.clang-format`).

## Generated code

Generated files are committed; regenerate them instead of editing:

| Files | Command |
| --- | --- |
| `lib/src/models/*.g.dart` | `dart run build_runner build --delete-conflicting-outputs` |
| `lib/src/native/bindings.g.dart` | `dart run ffigen --config ffigen.yaml` (needs libclang) |
| `lib/src/constants/*.dart` | `dart run tool/generate_constants.dart` |
| `native/src/bp_object_table.h` | `python3 tool/gen_object_table.py` |

After updating the bacnet-stack submodule, regenerate the constants and the
object table and run all tests, including the interoperability check below.

## Native code

Dart only talks to the engine API in `native/src/bacnet_plugin.h`;
bacnet-stack internals stay private to the native library.

- The engine is split into modules described in `native/src/bp_internal.h`.
  `bp_port_posix.c` is the BACnet/IP datalink for Linux, Android, macOS and
  iOS; Windows uses the bacnet-stack `ports/win32` sources.
- Compiler flags, defines and the source list are in `hook/build.dart`.
- Every engine call except `bacnet_plugin_wakeup` runs on the worker
  isolate: the stack is not thread safe. Network results reach Dart through
  the event buffer, never through callbacks.

## Tests

- Unit tests mirror `lib/src` (`test/codec/`, `test/native/`, ...); shared
  helpers live in `test/support/`.
- The native stack is process global, so client/server tests start the
  server in a second process (`tool/demo_server.dart`). Tag them with
  `@Tags(['integration'])`.
- Interoperability with the reference implementation, using the
  bacnet-stack demo applications built from a copy of the stack:

  ```bash
  make BACDL=bip server readprop
  BACNET_IFACE=lo BACNET_IP_PORT=47830 bin/bacserv 2002 &
  dart run tool/interop_client.dart 47830 2002
  ```

- Load tests:

  ```bash
  dart run tool/demo_server.dart 47811 1001 200 &
  dart run benchmark/load_test.dart --targets 127.0.0.1:47811:1001 \
      --requests 50000 --interface lo
  dart run benchmark/server_benchmark.dart 10000 lo
  ```

## Pull requests

- Keep changes focused and add tests for behavior changes.
- Document public API with `///` comments and list user visible changes in
  `CHANGELOG.md`.
- Use [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`).
- Follow ASHRAE 135 terminology and reference the clause for new services.

## Releases

1. Update `version` in `pubspec.yaml` and `CHANGELOG.md`.
2. Check the package: `dart pub publish --dry-run`.
3. Tag and push: `git tag vX.Y.Z && git push origin vX.Y.Z`. CI publishes
   to pub.dev with OIDC.
